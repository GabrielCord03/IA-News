## Design Specificity Verdict

**LLM assessment**: This reads as authored, not templated. The rust-band-as-structural-surface (not accent), the 5-color category-ink cycle instead of a rainbow, condensed display type reserved for stamped moments only, and the no-emoji stroke-icon set all commit to the naturalist-log world specifically. Glossary chips genuinely function as a "specimen index," category pages read as taxonomic drill-downs — the metaphor holds under interaction, not just skin-deep. Where it slips: the "rare sighting" mechanic, the one moment meant to feel special, is undermined by the real data it has to work with.

**Deterministic scan**: Detector ran clean except the one already-accepted `codex-grid-background` advisory (style.css:97, documented and signed off in DESIGN.md). Zero fresh findings across all 5 pages, style.css, and common.js. No false positives.

**Visual overlays**: Browser injection/screenshot capture was unavailable in this environment (headless pane not compositing frames); Assessment B substituted direct accessibility-tree reads, console/network checks, and computed-style measurements on the live GitHub Pages deploy instead. No user-visible overlay to point to this run.

## Overall Impression

Structurally and technically clean — zero console/network errors, zero fresh detector findings, correct heading hierarchy, correctly labeled form controls, all confirmed live on the actual deployed site. The remaining gaps aren't in the build quality; they're in whether the "field notebook" concept is load-bearing all the way through the data, not just the chrome. The biggest opportunity: make the rarity signal actually rare.

## What's Working

1. **Committed, restrained color system** — one rust-band surface, five category inks cycling across twelve categories, contrast verified 6.9-8.3:1 in both themes. Avoids the rainbow-dashboard trap while staying legible.
2. **Inline glossary chips deliver the stated product principle** — "Termos do dia" → `glossario.html#<term>` scroll-to verified working end-to-end live; terms really are one tap from their explanation, exactly as PRODUCT.md promises.
3. **Accessibility groundwork is solid** — confirmed live: exactly one `<h1>` per page, clean heading nesting, `#glossario-search` and `#categoria-select` both properly labeled, all decorative SVGs `aria-hidden`. Prior harden pass held up under independent re-check.

## Priority Issues

**[P1] Rarity signal fires on nearly everything.** Both real sample days are flagged `destaque_do_dia`, and 46% of all items (22/48) carry `relevancia: alta`. Why it matters: the one emotional payoff the whole "field notebook" concept promises — a rare sighting — can't read as rare when it's closer to a coin flip; it becomes visual noise the reader learns to ignore. Fix: tighten what qualifies as day-level/item-level "raro" (either in Hermes's classification or by adding a display-side threshold), or stop treating it as binary decoration and give it real signal. Suggested command: `/impeccable clarify` (or a Hermes-side data change, outside this skill's reach).

**[P1] One glyph, two meanings.** The flag icon means "day is a rare sighting" (badge) on index/dia AND "item is high relevance" (field-mark) inside every category section — same page, same glyph, two different real-world concepts. Why it matters: breaks recognition-rather-than-recall; meaning depends entirely on context, which is exactly the kind of ambiguity a naturalist log (precise by nature) shouldn't have. Fix: reserve the flag for item-level relevance only; give the day-level "rare sighting" badge its own mark. Suggested command: `/impeccable clarify`.

**[P2] `--ink-faint` fails WCAG AA contrast.** Measured directly: `#726752` on light paper `#e7e1d0` = 4.26:1; `#857a5f` on dark paper `#15130d` = 4.37:1 — both under the 4.5:1 normal-text threshold (this token was darkened in a prior pass but the fix undershot). It's used for the footer credit line, `.cat-count` pills, the select chevron, and — worst case — the loading/error `.state-msg` text itself. Fix: darken (light theme) / lighten (dark theme) further until both clear 4.5:1. Suggested command: `/impeccable harden` or `/impeccable audit`.

**[P2] Unbounded refetching in `categoria.html`.** `loadCategory()` fetches every day's JSON on every dropdown change with no cache — only `index.json` is memoized. Why it matters: DESIGN.md already flags history-at-scale as unverified; this is the concrete mechanism that will make category filtering slow on mobile data as days accumulate past the current 2-day sample. Fix: memoize fetched day JSON by date in a module-level map, keyed once per session. Suggested command: `/impeccable optimize`.

**[P3] Raw technical error states.** Confirmed live: `dia.html?data=2099-01-01` renders `Falha ao carregar ../data/2099-01-01.json: 404` verbatim, with no recovery link. Fix: catch block should render plain-language copy plus a link back to `historico.html`. Suggested command: `/impeccable clarify`.

## Minor Observations

- Badge microcopy inconsistent: "Avistamento raro" (dia/index) vs. "Raro" (historico) for the same concept.
- `dia.html` sets `document.title` to the raw ISO date, not the formatted date used everywhere else in the UI.
- Only `index.html` carries a `<meta name="description">`.
- `categoria.html`'s placeholder "Escolha uma ordem taxonômica." never actually displays — overwritten immediately by the initial `loadCategory()` call on page load.
- Touch targets measured live at mobile viewport: nav links 49×36px, theme toggle 84×31px, chips 132×34px — all clear the WCAG 2.2 AA 24×24 minimum, but sit under the 44×44 AAA target-size guideline in the browser's pointer:fine emulation. This matches the documented design decision (DESIGN.md: targets grow under `@media (pointer: coarse)`, deliberately not by viewport breakpoint) — the test environment can't force a coarse-pointer condition to confirm the real-device behavior, so this isn't a fresh miss, just an unconfirmed-by-this-run one.
- No A-Z jump index in the glossary; fine at 22 terms today, already flagged by DESIGN.md as unverified at scale.
