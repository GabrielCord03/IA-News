## 💰 Dicas de Economia e Performance

### Cache de prompt pode cortar até 90% do custo de entrada
*Tipo: economia_tokens*

Prompt caching reaproveita o cálculo da parte fixa do prompt, cobrando ~10% do preço normal nas leituras subsequentes. Regra: conteúdo estável no início, dinâmico no final.

**Fonte:** https://www.digitalapplied.com/blog/prompt-caching-2026-cut-llm-costs-engineering-guide

---

### Caso real: hit rate de cache subiu de 7% para 84% com uma mudança simples
*Tipo: economia_dinheiro*

ProjectDiscovery cortou 59% do custo de LLM movendo memória dinâmica do agente para fora do system prompt, colocando-a como mensagem de usuário ao final.

**Fonte:** https://www.digitalapplied.com/blog/prompt-caching-2026-cut-llm-costs-engineering-guide

---

### Batching aumenta throughput mas piora latência individual
*Tipo: performance*

Aumentar lote de 1 para 64 requisições em GPU A100 multiplicou throughput por 14x, mas latência individual aumentou 4x — escolha conforme o caso de uso.

**Fonte:** https://www.databricks.com/blog/llm-inference-performance-engineering-best-practices

## 👨‍💻 Dicas para Programadores

### Combine ferramentas por etapa do projeto: Cursor para velocidade, Copilot para revisão crítica
Cursor é ótimo para gerar features rápido; rodar Copilot depois em partes críticas (autenticação, rotas de API) evita bugs sutis antes que o projeto cresça.

**Fonte:** https://dev.to/paulthedev/i-built-the-same-app-5-ways-cursor-vs-claude-code-vs-windsurf-vs-replit-agent-vs-github-copilot-50m2

---

### Ordene o prompt corretamente para não quebrar o cache
Nunca colocar timestamp ou ID de sessão antes do bloco fixo do prompt, e nunca trocar de modelo no meio de uma sessão — isso invalida o cache e você paga preço cheio.

**Fonte:** https://www.flexera.com/blog/ai/prompt-caching-breakdown/

---

### Comunidade GitHub discute riscos de segurança de código gerado por IA
Discussão ativa reforça a importância de revisar manualmente qualquer código gerado por Copilot, Cursor ou Claude antes do merge, especialmente em autenticação e dados.

**Fonte:** https://github.com/orgs/community/discussions/194034

## 📚 Glossário do Dia

- **Pesos abertos (open-weight)**: Quando a empresa libera os parâmetros treinados do modelo para download público, permitindo rodar e modificar localmente, diferente de um modelo fechado só acessível via API paga.
- **Mixture-of-Experts (MoE)**: Arquitetura onde o modelo é dividido em sub-redes 'especialistas', mas só uma pequena parte é ativada por tarefa, tornando modelos gigantes mais rápidos e baratos.
- **Parâmetros**: Números ajustáveis dentro de uma rede neural aprendidos durante o treinamento; mais parâmetros geralmente significam mais capacidade de aprender padrões complexos.
- **Benchmark**: Teste padronizado para comparar desempenho de modelos de IA em tarefas específicas como programar, matemática ou responder perguntas.
- **Modelo de agente / agente autônomo**: Sistema de IA que toma ações sucessivas por conta própria (navegar na web, executar código, usar ferramentas) para completar uma tarefa maior.
- **Modelo de difusão**: Técnica de geração de imagens/vídeos que transforma ruído aleatório gradualmente numa imagem coerente; base de ferramentas como Midjourney e Stable Diffusion.
- **Modelo de mundo (world model)**: IA treinada para prever como situações do mundo real evoluem no tempo, útil para robôs e agentes 'imaginarem' resultados de ações antes de agir.
- **OCR (Reconhecimento Óptico de Caracteres)**: Tecnologia que converte texto em imagens/documentos escaneados em texto digital editável e pesquisável.
- **MCP (Model Context Protocol)**: Protocolo aberto da Anthropic que padroniza como modelos de IA se conectam a fontes de dados e ferramentas externas — o 'USB-C' da IA.
- **Sandbox / ambiente isolado de teste**: Ambiente virtual fechado usado para testar modelos de IA com segurança, sem acesso a sistemas reais ou internet.
- **Zero-day (vulnerabilidade de dia zero)**: Falha de segurança desconhecida pelos desenvolvedores e ainda sem correção disponível, especialmente perigosa quando explorada.
- **VLA (Vision-Language-Action model)**: Modelo que combina visão computacional e linguagem natural para gerar ações físicas diretas em robôs.
- **Compliance API**: Interface que permite que ferramentas de terceiros monitorem e classifiquem dados sensíveis usados em conversas com IA, para segurança e regulação.
- **prompt caching (cache de prompt)**: Técnica em que o provedor de IA guarda o processamento da parte fixa do prompt para não recalcular do zero em cada chamada, cobrando bem menos nas próximas vezes.
- **hit rate (taxa de acerto do cache)**: Percentual de chamadas que reaproveitaram o cache em vez de reprocessar tudo. Quanto mais alto, mais economia.
- **throughput vs latência**: Throughput é quantas respostas o sistema entrega por segundo no total; latência é o tempo de uma resposta individual. Aumentar um geralmente piora o outro.
- **batching (processamento em lote)**: Agrupar várias requisições para processar juntas na GPU, aumentando a quantidade total processada por segundo mas atrasando cada resposta isolada.
- **guardrails**: Regras de segurança embutidas em um modelo de IA para evitar geração de conteúdo perigoso ou indevido — às vezes bloqueiam também usos legítimos.
- **drop-in replacement**: Novo modelo/versão que substitui o anterior sem exigir mudanças de código ou integração.
